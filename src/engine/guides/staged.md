# Staged pieces — dependencies across results

A workflow supplies examples of technical dependencies. Apply the common operator policy for questions, model choice, settings, approval and saving; this guide does not redefine it. Requested outputs determine scope and quantity. Reuse available sources; preparation is not an extra deliverable by default.

## The questions card
Ask only missing user data under the current Auto/Guided policy. Do not ask again about a reference, view, style or count already specified. Distinct requested results need separate steps; count means candidates per image step, not different requested views.

## The look
An attached style source or explicit style governs the set. Auto decides unresolved creative choices; Guided may offer choices under the common question policy. Preserve unrequested properties, including pose, outfit and background when only the viewpoint changes.

## Pre-production first
When a recurring identity has no usable visual source, establish one image before steps that need that identity. A provided image or library item already satisfies this dependency. Do not generate a lock-up or neutral pose as a ritual. Candidates, extra sheets and separate review stages need a request or a concrete reason explained to the user; they are not automatic for multiple outputs.

## Reference sheet
A composite turnaround is one image containing several views: use reference_sheet with a source image, or a single image step for an invented source. Requested independent views are separate outputs, each derived from the same original source; use angle or image steps with refs and the user-selected compatible model. Preserve the requested number and order. Choose a consistent unspecified side creatively, not by asking again. Do not replace independent views with a grid or add a front view.
A source preparation is necessary only if no usable source exists. A sheet or candidate review can be offered when it serves the task; do not insert one unasked into a direct request. A temporary source stays temporary; saving follows the common library consent policy.

## Pilot first
A short test or partial pilot is an optional extra stage for an identified risk or material cost, explained before the user chooses it. Duration, a new model or multiple clips alone do not make it compulsory. If chosen, preserve existing references and run only the accepted portion; the remaining portion waits for the user's continuation. Never add a sheet to a pilot when identity sources already exist.

## One clip or several
Follow an explicit requested split. If a materially different deliverable remains ambiguous, ask one concrete choice under the common question policy. Use the model's documented duration/shot limits; if the requested duration cannot fit, explain the limitation and a feasible split. A script's total is total_duration; the app resolves unspecified step durations. A change in shots is not a change in identity.

## Sequence rules
Continuing the same take uses the previous clip's last frame or an appropriate frame of that scene. Independent scenes keep identity through the same references without forcing a previous first_frame. Neighboring shots may change shot size, camera or action coherently. Join only when the requested deliverable is a combined video and the workspace supports it; separate requested clips remain separate.

## Consistency across the set
Keep the selected model, references, aspect and style unless the requested change requires otherwise. Settings and input compatibility follow the shared contract; do not invent an alternative model policy inside a workflow. An operation's style and parameter inheritance are defined by its operation contract, not by a global image prompt rule.
