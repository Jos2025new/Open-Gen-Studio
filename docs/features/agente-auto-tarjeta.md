## Límites del modelo

Pedido del usuario (2026-10-24): que el agente sepa de antemano qué puede hacer el modelo, como el director de OpenArt, pero sin su lentitud ni tarjetas nuevas. Reglas en código que el agente no se puede saltar; el usuario ve una línea entre las acciones.

| Comportamiento documentado | Código | Test |
| --- | --- | --- |
| `find_models` dice lo que admite cada modelo de imagen y vídeo («takes: 720p, 1080p · 5–12 s · 16:9, 9:16…»), leído del esquema, el mismo que usa la tarjeta. Los esquemas que falten se cargan a la vez, con un tope de 2,5 s. El modelo del compositor ya llevaba sus límites en el contexto. | [modelLimits.ts](../../src/engine/agent/modelLimits.ts), [modelIndex.ts](../../src/engine/agent/modelIndex.ts) | [model-limits.test.ts](../../tests/model-limits.test.ts) |
| Cada `confirm_settings` deja la acción «Checked <modelo>» con sus límites. | [runtime.ts](../../src/engine/agent/runtime.ts) | [model-limits.test.ts](../../tests/model-limits.test.ts) |
| Una duración por encima del máximo de un clip, sea la que pide el agente o la que dice el usuario («45 segundos»), devuelve la llamada sin ajustes: el agente lo dice en una frase y pregunta con la tarjeta de preguntas de siempre: N clips unidos con `join_clips`, cambiar a un modelo que llegue (solo si existe alguno conectado) o un solo clip del máximo.
